Write Up

White Hat

We used ProPublica’s dataset: Civilian Complaints Against New York City Police Officers. We decided on this dataset because we weren’t particularly interested in environmental data and felt that the datasets with gender equality data and gentrification data were both too similar in theme to our Project 1 dataset, which looked at socioeconomic indicators.

For our white hat visualization, we created a bar chart that is both stacked and grouped. The chart explores civilians’ complaints by both complaint type and officer ethnicity. Complaint type is used for the main division (grouping of bars, x-position of group), and each group contains one bar for each ethnicity (x-position of ethnicity bar within group). We positioned the groups left-to-right in ascending order of complaint type severity.

To transform one aspect of the data, we simplified Board Disposition, which originally had 10+ disposition types. We created a custom calculated field, Board Disposition Simple, which combines the dataset’s original 10+ disposition types into 3 broad, easy-to-understand types: “Exonerated,” “Substantiated,” and “Unsubstantiated.” Each bar is subdivided and colored based on these simplified types. The ordering of the bar groups that I discussed above allows users to see a clear trend when it comes to substantiation rates.

This visualization represents the data accurately because it shows complaint data as a percentage of the category’s total number of complaints (where a category is a unique combination of Complaint Type and Officer Ethnicity). This allows users to compare data across groups based on proportions instead of raw counts. We chose this because raw counts can be misleading when one category (for example, white officers) is significantly overrepresented in the dataset.

One data transformation through interaction is sorting: users can use the “Sort by Board Disposition” dropdown menu to select one disposition type. Upon selection, all bars will automatically update so that the subsections for that disposition type are at the bottom. This makes side-by-side comparison easier because of the same visual starting point of 0%.

Black Hat

We used three other misleading techniques. For axis manipulation, we used a log scale with a fixed number of ticks. The log scale makes the numbers of complaints against officers of each race seem evenly distributed, even though most of the complaints are against white officers while Native American officers receive very few complaints. Since there are only four marks that are multiples of 10, it is hard to even tell that a log scale was used.

Additionally, the set-up skews the proportions for all categories so that it seems like there are far more complaints about categories at the bottom (like physical contact and poor use of authority) than bars at the top (barbaric remarks and maltreatment). For titles/labels, we renamed the complaint types to conceal severity (“Force” became “Physical Contact”) and to exaggerate severity (“Offensive Language” became “Barbaric or Abusive Remarks”). For marks/encodings, we chose a diverging color scale but assigned the colors in a “reversed” way so that the “severe” complaint types appear less serious. We assigned red to language-related offenses and light blue to force-related offenses.

Overview of Development Process

Based on our experience from Project 1, we decided to meet in-person whenever possible because we felt that in-person interaction makes it easier for us to work efficiently and provide real-time feedback for each other’s work. During the planning phase, all three of us came up with multiple ideas and discussed the pros and cons of each. For example, we knew we wanted to create something that would show how raw counts alone and percentages alone do not show the full story, but we disagreed about which one was “worse” and how we’d translate that into a visualization.

We spent about 7 hours developing our application. Because we used Tableau, we were able to spend significantly more time brainstorming, trying out different ideas, and debating best strategies instead of getting stuck “in the weeds” of manual coding and debugging. Xael created several exploratory visualizations to help us better understand key variables in the dataset and determine which ones would make for a compelling story. This work covered different types of charts (bar, line, area, etc.) and user interactions so that we could look at several potential combinations.

Stephanie worked on the logic and the chart for the black hat visualization, and Ankita did the same for the white hat visualization. Xael and Stephanie both found the resources needed for advanced tooltips, calculated fields, and parameter actions (creating user interactions in Tableau). Ankita wrote all of the write-up sections. Lastly, Xael set up the repository and configured all headings for organization.

Extra Credit

For extra credit, we implemented two advanced interactions: worksheet actions for automatic sorting and tooltip filtered scatterplot.

One of our major transformations was sorting using a dropdown interaction. As a shortcut, we also added an advanced interaction using worksheet actions: users can simply click on one such subsection on any bar, and all bar-subsections with the same board disposition will be moved to the bottom. Tableau’s “worksheet action” uses select/hover/menu to change the value of a parameter; in our case, we chose to “select”/click on a bar in order to set the parameter value for the dropdown.

The second is customized tooltips. Users can already hover over a subsection of a bar to view the values for the default fields (Board Disposition Simple, Complaint Type, and Officer Ethnicity) as well as the precise percentage value for that combination as a proportion of the bar. We extended this to also include the average complainant age. Each tooltip also includes a graph that shows the number of complaints within that category (ethnicity, Board Disposition, and Complaint Type) received each year from 1985-2020. We opted to use dots instead of a line (traditional line graph) because we wanted to ensure clarity about years with no complaints without the visual eyesore of multiple breaks in a line.
